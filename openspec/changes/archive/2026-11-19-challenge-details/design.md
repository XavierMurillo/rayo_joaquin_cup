# Challenge details design

Use the current Version III Challenges grid as the entry point. Each challenge gets an explicit **View challenge details** action that opens an in-page dialog. Follow the existing team dialog's native keyboard behavior, including Escape and focus return. Keep the dialog scrollable when instructions exceed the viewport.

Keep the preparation summaries and add an optional structured detail record to each module in the edition data. The local Python API serves the record alongside the existing module data. Render confirmed guidance as short labeled sections, and display a clear status when specific instructions are awaiting release. Only include a reference image when one is supplied or approved, and label illustrative diagrams as references.

Before release, compare the detailed instructions with the official guidelines and the organizer's event-day decisions. Review the general event-day notice when published details make parts of it outdated.

Use a wide dialog with instructions and the reference illustration side by side on desktop. Stack them on narrow screens and keep the dialog vertically scrollable. The supplied illustrations contain example parameters and rules, so identify them as illustrative before the image and keep the written instructions authoritative until the organizer confirms those values.
